更新时间：2026-10-23T04:13:27.892Z。目录含 17 个电影/语言版本（14 部独立影片）与 2 个直播频道，共 19 条。

## 验证标准

- 必须从实际媒体分片的 H.264 SPS、MP4 sample entry、ffprobe 或 HLS master 的分辨率字段读取尺寸，并且清单与真实分片可达；片名、分类、`4K修复` 标签不作为证据。
- 满幅 UHD 为至少 3840×2160；影院裁切画幅接受宽至少 3840、高至少 1600，界面展示真实宽高，不能冒充满幅 2160。
- 本轮电影均在本机 ffprobe 读取媒体头，并在东京以并发 2 逐项重新请求详情、清单及一个中段分片，从 SPS 再读实际尺寸。只按东京通过项生成最终目录。
- 验证的是编码画面尺寸，不证明原始摄影/母版分辨率、无损画质、HDR、广告状况或所有设备的解码能力。没有用测试片充当影视片源。

## 点播扫描

1. 对当前配置与上游历史候选、公开帮助中心中的茅台/快车/红牛接口，共 27 个 API，搜索 4K、2160、杜比及对应 4K 分类。发现报告为 `4k-discovery-local.json` / `4k-discovery-tokyo.json`。
2. 首轮 33 部样本均读到尺寸，只有《攻壳机动队4K》达到影院裁切 4K；其余许多 4K 分类项目实际为 720/1080。
3. 扩展最大/快车 4K 分类前两页，共 81 个条目，完整结果为 `4k-media-focused.json`。其中 29 个跨源条目达到真实 4K（21 个满幅 2160 与 8 个裁切画幅）。
4. 这 29 个条目全部在东京再次通过媒体头与分片检查，证据为 `4k-vod-tokyo.json`。按片名/语言版本去重，优先现有最大资源，得到 17 条电影目录。
5. 最大资源原已在默认 11 源中，顺序保持不变。快车的公开关键词接口返回「暂不支持搜索」，因此没有把它加入通用搜索默认源；仅收录其通过验证的 4K 点播条目。API 标称 4K 分类数量不等于真实 4K 片库数量。

点播来源公开接口可查，不涉及付费账号、云盘授权、DRM 解密或私有 token。提供方没有在这些接口中附逐片版权授权证明，因此目录只记录技术验证结果，不标注为官方正版影视库。

## 直播与失败候选

- 河北与苏州由本机 ffprobe 识别为 H.264、3840×2160、25 fps，音频 AAC，证据为 `4k-ffprobe-local.json`；东京 SPS 证明分别见 `4k-live-tokyo.json` 与 `4k-live-tokyo-http.json`。
- 苏州公开 HTTPS 入口证书过期（`CERT_HAS_EXPIRED`）；目录使用同一播出域可公开访问的 HTTP 入口，由应用 HTTPS 代理转发。没有关闭证书验证。
- 河北复测出现过一次瞬时 fetch 失败，目录保留成功验证时间，不承诺持续无中断。
- 第三方 Gist 中湖南候选经本机 ffprobe 读取为 HEVC 3840×2160/25 fps，但链接包含播出鉴权路径，稳定性和东京入口尚未完成验证，暂不收入最终目录；`4k-hunan-candidate.json` 不保存该鉴权地址。
- Gist 只是发现线索，不能以作者旧测试结果代替本轮验证。

## 文件与复测

`4k.json` 是产品读取的最终清单；各 `4k-*.json` 为有日期和出口的证据。报告不保存分片或含时效 token 的播放地址。探测私有中间文件在被 Git 忽略的 `deploy/.artifacts/` 与主机 source-audit 目录，不打包进应用。

脚本为 `scripts/infra/probe-4k-discover.mjs`、`scripts/infra/probe-4k-media.mjs`。媒体脚本通过 `PROBE_CODEC_HELPER` 读取由现有 `src/lib/codec-parse.ts` 编译的 CommonJS helper；本机可用 `PROBE_FFPROBE` 指定 ffprobe 路径，东京通过 SPS 直接解析，不编译或安装解码器。
