# 以 4K 为主的片源筛选 · 2026-10-23

## 用户标准与当前结论

用户要求的是**可用来源本身的片库中，大部分视频实际达到 4K 或更高画质**。不能以混合资源站里存在若干 4K 条目、站名含 4K、或筛选出的单片目录代替这个要求。

用户随后明确只接受：**免费、无需额外账号、直连播放**。网盘账号/会员、付费媒体库及需要额外登录的方案均不在本轮接入范围内。

本轮尚未核实到符合上述标准、免费匿名直连、可直接接入现有 LibreTV 的新增电影库。这个结论只覆盖本轮查到及测试过的对象，不等于宣称互联网上不存在这样的来源。

普通源扩展和精选单片扩展均未发布。正式配置仍为 11 个默认源、19 条 4K 目录；待发布配置已撤回，服务未重启，现有账号与记录未改变。

## 实测证据

网页公开帮助页与 GitHub 公开配置合并后，88 个去重 API 地址经过初测。35 个有正片阳性结果的接口再做三个片名的详情、真实中段媒体和时长复核，105 次中有 101 次可达，全部读到编码尺寸，最大宽度 1920；没有一个样本达到 4K。这些接口包括备用域名，样本也不能视作 101 部独立影片。

先前“4K电影”分类的已有媒体头证据如下，失败/未核实样本保留在全部抽样分母：

| 分类范围 | 抽样条目 | 清单及中段可达 | 实际编码 4K | 全抽样中已证 4K | 可达样本中的 4K |
| --- | ---: | ---: | ---: | ---: | ---: |
| 最大，首批 40 条 | 40 | 34 | 13 | 32.50% | 38.24% |
| 最大，后续增量 58 条 | 58 | 33 | 29 | 50.00% | 87.88% |
| 最大，两批合并去重 | 98 | 67 | 42 | 42.86% | 62.69% |
| 快车，首批 40 条 | 40 | 37 | 16 | 40.00% | 43.24% |

这些是分类默认顺序分页、去旧标题和限时抽样，**并非随机抽样，更不是整个资源站的画质分布**。后续 29 条仅为本地筛出的阳性项，东京全部通过也不能推导来源整体具有 100% 4K。尤其不能去掉失败条目，用 29/33 掩盖 25 个失败/未核实条目。

编码尺寸按 H.264 SPS 等实际媒体头读取，影院裁切画幅保留真实宽高；3840 宽不单独证明原生母版、无上采样、HDR、原盘码率或完整播放稳定性。

## 公开来源与协议限制

- [TVboxorg 公共配置](https://github.com/TVboxorg/TVbox/blob/main/dist/official.json) 和 [MoonTV 电影配置](https://github.com/shijianus/moontv-source/blob/main/config-films.json) 是发现线索，列表中的名称与健康状态不是整个媒体库的画质证明。CSP/JAR/网盘规则需要专门协议实现，不能作为当前 AppleCMS API 直接填入。
- [4kvm-source](https://github.com/op948687/4kvm-source) 的品牌不能证明片库画质；公开响应出现 iKun/1080P 线路，协议也不同于当前 AppleCMS。没有取得其全库真实尺寸占比证据。
- 上述 GitHub 原型与 4kvm 原站分别核对，不混同。原站的[动画播放页](https://www.4kvm.tv/play/cgzq7f3tf)和[电影播放页](https://www.4kvm.tv/play/ch4iax9g1)公开列出“成为会员”享受“4K超高清”的权益，不能据站名将它列为已验证免费匿名 4K 主源；未购买、登录或绕过限制。
- Jellyfin/Emby 是媒体库软件或协议，不附带一个全 4K 内容库。用户自有或获授权媒体库可以逐文件核验，再筛选、接入；[Jellyfin 电影文档](https://jellyfin.org/docs/general/server/media/movies/)说明了用户媒体文件与多版本的组织方式。
- 115、阿里云盘等应通过用户已有账号与平台允许的授权方式读取用户的文件。它们本身不保证用户文件是 4K，也不能把公开分享链接、会员标签或网盘索引当作已验证的 4K 播放服务。
- HEVC、HDR、音轨与容器会影响实际设备直播放；不同客户端能力需另外验证，参见 [Jellyfin 编码支持说明](https://jellyfin.org/docs/general/clients/codec-support/)。不能通过服务器降为 1080p 后仍声称以 4K 播放。

上述媒体库/网盘模式仅用于解释筛选边界，按用户最终选择已排除，不作为本轮后续推荐。

用户限定免费匿名直连后，另审查六个 GitHub 仓库及四个网页候选：网盘搜索/导航推广/历史混合清单不能作为媒体源；BingeBang 的本地请求 403、CineBolt 请求失败、Donkey 仅取得聚合目录，均未取得“免费匿名媒体可达 + 整库大部分实际 4K”的证据。未将这些状态外推为永久不可用，也未用测试片或动画短片库替代用户要的电影/剧集片源。

## 后续准入

1. 确认是媒体来源及可用权限，记录是否需额外账号、会员、付费、直链刷新或协议适配。
2. 从整个目标库跨页、跨时间及影视类别取样；若仅限一个 4K 子库，清楚标明范围，不代表提供方全库。
3. 分开报告可达率、已证 4K 占全部抽样比例、已证 4K 占可达样本比例，以及失败/未知数量。用户未指定数值阈值；80%可作为优选目标，不能冒充用户的硬性要求。
4. 从实际最高可用媒体版本读取尺寸、编码与码率，必要时检查 HDR/原盘信息，保留上采样和完整影片验证边界。
5. 通过电影及剧集的真实手机、平板、TV 播放检查后再接入。现有东京小内存主机不承担新的 4K 转码负载。

本机忽略目录 `deploy/.artifacts/` 保留了发现、采样与归并原始报告；没有购买服务、注册第三方账号、执行陌生插件或使用他人凭据。
